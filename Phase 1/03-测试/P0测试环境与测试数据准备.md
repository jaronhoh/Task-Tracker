### 执行门槛

- **UI 基础用例**：应用可运行即可开始，但须记录版本和测试数据。
- **API 用例**：须先确认 API Base URL、测试凭证及错误响应格式。
- **并发/事务/ID 永不复用用例**：须具备隔离测试数据库和服务端/持久化证据；不能仅凭 UI 显示判定通过。
- **Blocked** 只表示缺少必要能力或前置条件，不得记作 Pass。
- 所有测试数据必须位于专用测试环境，禁止对生产数据执行故障注入。

## 4. 必须保存的基线与证据

对每个涉及拒绝、原子性或回滚的用例：

1. 执行前保存 Task/Customer 完整字段快照。
2. 记录请求时间、服务端时间（Malaysia Time，UTC+8）、请求方法、路径、请求体及关联请求 ID。
3. 保存 HTTP 状态码和完整错误响应；不得只记录“失败”。
4. 执行后重新读取记录并与基线逐字段比较。
5. 并发场景另保存每个请求的发送顺序、服务端接收顺序、响应顺序和最终数据库状态。
6. 事务/ID 场景保存服务端日志或数据库证据；仅有页面截图不足以证明事务回滚或 ID 永不复用。
7. 每条用例填写实际结果、证据链接、执行人、环境版本、执行日期和缺陷编号。
